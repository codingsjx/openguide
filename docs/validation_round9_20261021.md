# 第九轮：真实失败、复现与边界（2026-10-21）

本轮不更改选题与申报方向。目标是让功能和结论更符合实际，不以测试数量替代真实用户效果。

## 1. 五仓库固定源码检查

`benchmark.readiness_audit` 从既有 Git checkout 的固定 SHA 读取资料，不调用模型、不执行上游命令。报告同时保留待确认项、未知目录和结构约束结果；结构检查通过不表示整个上手流程可运行。

| 仓库 | 本轮观察与修复后的边界 |
|---|---|
| Requests | 有原文克隆、开发依赖与测试命令；运行环境和 issue 仍需确认 |
| Click | 安装资料在当前快照覆盖内不足；取得的是专项 tox 命令，不能称为通用新手基线 |
| Cookiecutter | 不再推荐 `your_name_here` 克隆模板；局部 pytest 命令明确标注范围 |
| Mocha | 当前资料抽取下环境及测试仍有缺口；不从 package.json 凭空补出未经当前核验机制支持的命令 |
| Camelot | 不再把 `nox --version` 当作测试；保留原文测试入口，未实际运行 |

修复前后记录分别为 `benchmark/reports/multi_repo_readiness_before_fixes_20261021.json` 和 `multi_repo_readiness_20261021.json`。两个记录都不能当作命令成功率或新手成功率。

## 2. 新的真实模型对照没有全部成功

两个固定仓库、每仓库两次重复、四组（单次生成、全局 RAG、分视角生成、同输出审计），使用相同输入快照，完整保留失败。两批运行分别记录在 `controlled_validation_20261021.json` 与 `controlled_validation_fence_20261021.json`。每批 16 组中 8 组可计分，24 次请求有 24 份响应，服务报告各 84,106 tokens；源码在各自运行期间未变化。第二批增加完整 JSON 围栏兼容，但仍严格拒绝非法控制字符，因此失败未被改记为成功。

Click 的两次分视角输出在明示专项命令参考范围内匹配，全局组在该窄范围内未匹配。这不能证明更适合新手：参考任务偏向专项命令提取，完整基线和用户效果未测。Requests 的对应组未完成，不能作跨仓库普遍优势结论。不同处理规则、不同源码版本的两批结果不合并成一个提升百分比。相同提示下部分响应内容重复，也不把重复运行当然解释为独立随机样本。

模型身份、用量及缓存信息以服务返回为准，未独立验证模型权重。两份参考仍待独立人工复核，`quality_claim_eligible=false`。

## 3. 产品端兼容及同输出回放

严格实验客户端继续拒绝非法 JSON。产品客户端可读取完整对象中字符串内的原始 LF/CR/TAB，保留相同字符与修复标记；不补括号、不推测被截断值、不接受其他控制字符，解析后照常核验引用和命令。原始响应仅存本机。

单次 Requests 产品生成使用 4 次真实请求、4 份响应，服务报告 10,030 tokens。随后对同一组响应做确定性回放：保留 A/B 的可核验成果，D 原先缺少依据的建议改为 4 项有原文的贡献规范，专项 typecheck CI 安装不再作为必需命令。该回放新增模型调用为 0，不冒充新的模型抽样、命令执行或用户贡献结果。

原始问题样例 `output/guides/requests-product-20261021.json` 已标记为历史错误分析；当前回放结果为 `requests-audited-replay-20261021.json`。对应统计见 `output/qa/product-validation-20261021.json` 与 `product-audit-replay-20261021.json`。

## 4. 新目录与锁定依赖复现

默认核心安装移除向量模型依赖，向量功能通过 `vector` 可选依赖保留。新目录、新虚拟环境按 uv.lock 安装 23 个运行包（含本项目），未安装 Chroma 或 sentence-transformers，没有复制凭据；真实 HTTP `/health` 返回 200。再安装锁定开发依赖后，191 项后端及评测测试通过。

前端从新目录按 pnpm 锁文件安装，10 项测试、lint 和生产构建通过。首次把验证目录放在父仓库忽略目录内，lint 未找到文件而失败；随后在仓库外的新目录按原命令重验通过，保留这个验证环境问题。下载缓存被复用，不宣称全程没有缓存。

详细结果与候选源码摘要见 `output/qa/clean-start-verified-20261021.json`。本机没有 Docker，因此本机原生结果不能视为容器启动结果。已修复 Docker 构建顺序及可选依赖开关，加入 CI 的实际镜像构建、Compose 启动、页面与同源 API 检查；容器结论以该提交的 CI 日志为准。
