# 模拟新手走查后的断点修复（2026-10-22）

本轮沿用开源新手贡献向导方向，解决“有指南但遇错后无法继续、找不到任务、无法整理贡献材料”的断点。下面记录代码修复、实际页面验收和证据边界；不是国奖效果结论或真人研究结果。

## 实现与原因

### 错误恢复

原规则只要日志包含 `connection` 就提示依赖源超时，因此 `test_different_connection_pool_for_tls_settings_verify_bundle_unexpired_cert` 这个用例名称会误触发网络提示。

现在分别识别本地证书路径、文件缺失、证书信任、网络异常和解释器/依赖问题。具体证书路径错误走确定性检查，不依赖模型服务；只读检查独立标为工具提供的通用方法，不冒充仓库原文。路径只接受保守的仓库相对路径字符集，禁止将日志中的任意字符串拼进命令。网络提示区分安装下载和测试访问的端点。

检查步骤包括解释器/工作目录、文件及父目录类型、Git 文件模式及其判读方式。相关仓库资料按目标路径过滤，避免把过期证书的生成说明附到有效证书路径问题上。GitHub 采集失败时，报错帮助仍返回通用本机检查，标明没有核验仓库原文。检查与修复没有自动执行，实际结果仍需使用者记录。

### 任务入口

候选不再依赖模型恰好保留 issue 引用。`issue_discovery` 从真实采集数据提供编号、固定仓库内链接、标签、核对事项及快照取得时间。过滤 PR、明确关闭、已锁定和已有负责人的任务；负责人或锁定字段缺失时提示用户核对，不能据此断言无人负责。

两个标签检索没有可用结果时，额外取最多 30 条开放列表响应，排除 PR 后作为普通 issue 浏览样本。它们不计入画像中的新手标签任务，也不宣称适合新手。普通样本保留在独立字段，文档固定版本采集不会丢掉它们。

页面区分候选、普通样本、空结果、采集失败和受阻状态；提供 good first issue、help wanted、全部开放 issue 的 GitHub 检索入口。正文出现 PR/compare 链接时提醒核对已有实现。最新讨论、关联 PR 和维护者参与政策仍须人工确认。

### 实际改动与草稿

贡献工作台在 C/D 阶段保留同一任务输入。候选可以填入任务标题和链接；也允许有来源说明的人工选题。用户填写实际修改摘要、仓库相对路径、可选标准文本 diff、实际改动基准和验证记录，再生成可复制、下载的 Markdown 草稿。

缺少修改记录时禁止生成；测试标为通过必须有命令、退出 0 和结果摘要，标为失败须非零退出码。未运行、失败、局部范围与未经核验的记录会原样保留。指南参考版本与用户填写的改动基准不同会提示核对，不将两者混为同一次执行。文件路径可从粘贴的 diff 解析，但工具不宣称该 diff 来自本机或对应当前提交。

表单仅保留在当前页面，步骤切换不会清空；离开、刷新或重新生成指南前需要导出，尚无工作记录导入/自动恢复。没有自动修改上游文件、运行命令或向 GitHub 提交 PR 的功能。本轮下载的草稿是本次 OpenGuide 修改的审阅材料，不是上游 Requests 的贡献记录。

### 其他直接相关体验

- Python 可选环境说明支持直接使用 venv 解释器，避免依赖终端激活或把包装进系统 Python。
- 命令支持复制完整文本；“仅查看下一步”不标记完成。
- 已有有效克隆/测试动作时，合并重复且没有依据的“准备 Git 克隆仓库”“确认测试基线期望”空项，重新计算步骤和前置引用。
- 中文标题检索没有命中时，“为什么”可回到当前已知出处的相邻原文，仍逐字核验。
- 保存指南导入检查新增候选形状和链接，拒绝指向其他仓库或脚本协议的候选。
