# 隐私与授权说明

本文件按赛事对"隐私与授权说明"的要求，如实说明 OpenGuide 采集什么数据、如何存储、
发送给谁，以及授权与合规边界。

> 一句话：**只读公开仓库信息；不采集用户隐私；不落盘任何密钥；不向第三方发送仓库以外的内容。**

---

## 1. 数据采集范围

### 1.1 采集什么

OpenGuide 只通过 **GitHub 公开 REST API** 读取**公开仓库**的以下信息：

| 类别 | 具体内容 | 用途 |
|---|---|---|
| 仓库元数据 | 名称、描述、star/fork 数、open issue 数、默认分支、许可证、推送时间 | 仓库画像 |
| 语言占比 | 各语言字节数 | 仓库画像的"语言构成" |
| 根目录清单 | 根目录文件名（用于识别 README / Makefile / pyproject.toml 等） | 构建方式识别 |
| 文档正文 | README、CONTRIBUTING、LICENSE、docs/ 下的开发/安装类文档、构建文件 | 四视角索引与指南生成 |
| 文件树 | 仓库文件路径列表 | 架构视角与证据校验 |
| issue | 带 `good first issue` / `help wanted` 标签的 issue 标题、正文、标签 | V4 issue 槽位 |
| 提交活动 | 近 30 天提交条数 | 活跃度信号 |

**全部为公开信息**，与任何浏览器匿名访问 GitHub 能看到的内容一致。

### 1.2 不采集什么

- ❌ **不采集任何用户隐私数据**：无账号体系、无登录、无 Cookie 追踪、无埋点、无遥测
- ❌ **不读取私有仓库**：只处理公开仓库
- ❌ **不 clone 完整源码**：只按需拉取上述文档与清单，不下载代码正文
- ❌ **不要求用户提供 GitHub 账号**：`GITHUB_TOKEN` 完全可选，留空也能运行
- ❌ **不采集使用者身份信息**：不记录谁在什么时候查询了哪个仓库

### 1.3 关于可选的 GITHUB_TOKEN

留空时以匿名方式调用 GitHub API（限流较低，约 60 次/小时）。填写一个 token
可提升限流额度，让演示更稳定。若填写：

- 建议使用**只读**权限（经典 PAT 的 `public_repo`，或细粒度 PAT 的
  `Contents: Read` + `Metadata: Read`）
- 仅存放于本地 `backend/.env` 或部署时的环境变量，**已被 `.gitignore` 排除**
- CI 配有密钥扫描（`.github/workflows/ci.yml` 的 `secret-scan` 任务），
  提交内容中若出现密钥特征会直接失败

## 2. 数据存储

| 位置 | 内容 | 生命周期 |
|---|---|---|
| `.cache/` | GitHub API 响应（JSON） | 本地磁盘；带 TTL（默认 3600 秒）自动过期清理 |
| `.chroma/`（可选） | 四视角向量索引 | 本地磁盘；仅在使用 chromadb 时产生 |
| 进程内存 | 会话内的 LLM 配置（含 Key） | **进程重启即消失** |

以上目录均在 `.gitignore` 中排除，**不会随代码提交**。删除对应目录即可彻底清除。

> Docker 部署时，`.cache/` 与 `.chroma/` 挂在命名卷上；执行
> `docker compose down -v` 即可连同数据卷一起清除。

## 3. 密钥处理

**这是本项目最明确的红线：Key 不落盘、不进日志、不回显。**

| 场景 | 处理方式 |
|---|---|
| 页面右上角「设置我的 LLM」填写 | 只存**当前进程内存**，不写磁盘；接口返回只给 `configured: true/false`，**不回显 Key** |
| `backend/.env` 填写 | 仅本地文件，已被 `.gitignore` 排除；CI 密钥扫描兜底 |
| 日志 | 代码中不存在打印密钥的路径；异常信息只带 URL 与状态码 |
| 前端 | 从不持有也不展示已保存的 Key（只能重新填写覆盖） |

## 4. 第三方服务与数据出境

### 4.1 大模型服务（可选）

若配置了 LLM，OpenGuide 会把**检索到的仓库公开文档片段**与该阶段的提示词发送给
所配置的端点，用于生成指南文本。发送范围**严格限于**：

- 该阶段检索命中的仓库文档片段（公开信息）
- 阶段指令与输出格式要求

**不会发送**：用户身份、Key 本身、与当前仓库无关的任何内容。

用户可在页面「设置我的 LLM」里把端点指向任意 [OI] 兼容服务；
**使用第三方服务前请阅读 [`third_party_disclosure.md`](third_party_disclosure.md)，
并自行确认该服务的数据处理条款。**

### 4.2 不配置 LLM 时

完全不产生任何外部数据发送——生成走本地确定性启发式路径，
向量检索若走回退模式也在本地完成。

### 4.3 本地嵌入模型（可选）

使用 chromadb 时，嵌入模型在**本地**运行，仓库文本不离开本机。
首次使用会从模型仓库下载模型权重（一次性）。

## 5. 授权与许可

| 项 | 说明 |
|---|---|
| 本项目许可 | **MIT**（见 [`../LICENSE`](../LICENSE)） |
| 第三方组件 | 逐项列于 [`third_party_disclosure.md`](third_party_disclosure.md)，按其自身许可使用 |
| 处理的仓库内容 | 仅读取公开信息用于分析与展示；不复制、不重新分发仓库源码 |
| 生成内容 | 指南中引用的原文片段用于**出处标注**，归属原仓库及其作者 |

### 5.1 开源叙事与克制边界

本项目**不自称纯开源**：

- **自主实现**：编排管线、四视角分层索引、证据锚点校验、四层评测体系
- **开源依赖**：chromadb / sentence-transformers 等（许可见披露文件）
- **商业服务**：通用大模型走商业 API 调用，不硬吹"纯开源模型"

这一边界同样适用于评测叙事：样例与烟测**不宣称生成质量**，
任何质量数字必须能回溯到人工复核过的 golden 仓库集。
