# 生成模式与提示分层改进（2026-10-22）

用户截图中的四条黄色说明分别涉及语言采集失败、固定资料版本、Windows 符号链接和 issue 阶段规则入口。它们原来全部作为 warning 展示，且规则结果没有记录是手动选择还是 AI 回退，导致无法从页面判断实际状态。

## 改动

- 后端新增 `requested_mode`，记录本次请求为 AI 或规则。新增 `stage_fallbacks`，按阶段记录未配置、超时、认证/权限、限流、其他模型请求错误、无效输出或出处未通过核验。仅输出固定原因代码，不把服务商原始错误、请求 URL 或凭据写进元数据。
- 手动规则模式不会被标成 AI 失败。AI 阶段通过模型生成后若被证据核验替换，单独记录出处原因，不混作模型服务故障。严格实验仍按原约定抛出模型错误，不静默回退。
- 顶部显示一句明确的模式摘要；当前阶段显示实际来源和已记录的原因。完整阶段信息可展开查看。
- 已识别的资料采集失败保留为醒目的黄色区域，提示本份指南只覆盖已取得的资料。在线结果提供标明规则或 AI 模式的重新生成入口，对当前结果对应仓库重试采集；已知原请求模式时沿用该模式，旧结果模式未知时按钮明确标为“用 AI 重新生成并重试采集”。
- 符号链接风险放进“操作前核对”，版本 SHA 和独立 issue 快照说明放进“资料版本与核验说明”；完整内容仍可展开，SHA 可复制。其他未归类提示保留在“其他提示”中。
- 追问中的版本说明也复用分层展示，避免每次追问再堆一排黄色提示。
- 老指南没有记录请求模式时明确显示“触发原因未记录”，不反推用户点过哪个按钮。保存/导入保留新元数据并验证原因代码；离线导入不提供联网重试按钮。
- 窄屏中的重试按钮放在说明下方，避免挤压正文。

## 验证

本轮后端与 benchmark 测试 **215 passed**（1 条依赖弃用警告），前端 **25 passed**；lint 和生产构建退出 0。构建体积提示仍存在，未将其当成构建失败。

浏览器在本地 Requests 页面分别验证：

1. 点击“快速（本地规则）”，实际导出结果为 `requested_mode=rules`、`stage_fallbacks={}`，页面显示“规则模式 · 由你选择”。
2. 依据用户截图构造明确标注的离线回放：只有语言采集失败进入黄色区域；符号链接、各阶段来源和完整版本说明可以展开。回放未声称 GitHub 当前仍失败，也未猜测截图当时的按钮选择。
3. 发起一次真实 AI 生成，实际返回：A 阶段模型超时后规则回退、B 阶段保留 AI 输出、C/D 阶段因出处核验未通过回退。页面与导出 JSON 一致，直接显示每个阶段的原因。

材料位于 `output/qa/status-clarity-20261022/`：`rules-live.json`、`ai-live.json` 为真实页面导出；`screenshot-replay.json` 是标明来源的回放测试文件；截图分别展示规则摘要、回放中的采集提示、展开的完整说明和真实 AI 回退原因。

## 范围

本轮解决的是状态可解释性和提示展示，不代表模型服务超时、资料采集不稳定或原始证据不足已全部解决。实际 AI 超时保留在结果中，没有用规则输出冒充 AI 成功。警告分组对现有提示文字做兼容处理，新增提示保留在其他提示中，后续应随新提示类型更新分组。

本轮没有重新执行 Requests 的安装/测试或创建上游贡献，也不计为真人试用、独立复核或模型效果对照实验。项目方向保持不变。
