# 演示脚本（现场 3 仓库）

**用途**：评审现场 / 录制视频时按本脚本走，保证"输入 URL → 出带证据的路线图"稳定复现。
**时长**：约 3-5 分钟（3 个仓库）。
**口径**：现场只展示**生成过程与证据链**，不当场宣称生成质量；质量数字一律引用
`benchmark/reports/` 里人工复核过的 L2 结果（见 `benchmark/README.md` 的口径红线）。

---

## 0. 启动（二选一）

### A. Docker 一键起（评审冷启动推荐）

```bash
cp .env.example .env        # 可选：填 GITHUB_TOKEN / LLM_API_KEY
docker compose up --build
# 浏览器打开 http://127.0.0.1:5173
```

### B. 本地开发起

```bash
# 终端 1：后端
cd backend && uv sync && uv run uvicorn backend.api.main:app --port 8000

# 终端 2：前端
cd frontend && pnpm install && pnpm dev
# 浏览器打开 http://127.0.0.1:5173
```

**演示前 5 分钟检查**（避免现场翻车）：

- [ ] 后端 `/health` 返回 `{"status":"ok"}`
- [ ] 页面能打开、右上角「设置我的 LLM」状态符合预期
- [ ] **预热**：把下面 3 个仓库各跑一遍（见 §2），让 GitHub 响应缓存与向量索引落盘；
      现场再跑就是秒级，且不消耗 GitHub 限流
- [ ] 若现场网络不稳：**不填 LLM Key**，直接走「快速(本地规则)」路径（无需外网模型）

---

## 1. 演示主线（每个仓库 60-90 秒）

固定话术结构：**输入 URL → 看体检卡 → 看路线图 → 点开一条证据 → 试一次追问**。

| 步骤 | 操作 | 讲解要点 |
|---|---|---|
| 1 | 输入仓库 URL，点「生成路线图」 | "只抓决策相关信号，不 clone 全文" |
| 2 | 切到「仓库体检」 | 语言构成 / 构建方式 / good-first-issue / 活跃度 |
| 3 | 切回「贡献指南」 | Stage A 环境搭建 → B 测试基线 → C 挑 issue → D 首 PR |
| 4 | 点某一步的**证据标签** | "每条建议都能点回仓库真实文件/issue —— 无证据不宣称" |
| 5 | 点「这步太粗」 | 现场演示追问，回答按步骤所在阶段检索 |

---

## 2. 三个演示仓库（按推荐顺序）

### 仓库 1：`https://github.com/psf/requests`（主秀）

- **为什么选它**：Python 生态最知名库之一，README/CONTRIBUTING/Makefile 齐全，
  评委认知度高，痛点共鸣强。
- **预期看点**：A 阶段给出真实安装命令、B 阶段给出真实测试命令，
  每条都挂到具体文件。
- **讲解**："注意 B 步的测试命令来自 Makefile，而不是模型编的。"

### 仓库 2：`https://github.com/pallets/click`（换一个技术栈口味）

- **为什么选它**：Python CLI 框架，pyproject + pytest，构建面干净，
  用来证明"换一个仓库照样出路线图"（不是给 requests 写死的）。
- **预期看点**：体检卡的构建/测试识别、C 阶段能挑出 good-first-issue。

### 仓库 3：`https://github.com/mochajs/mocha`（跨语言）

- **为什么选它**：JavaScript 项目，package.json + npm test，
  证明管线不绑定 Python。
- **预期看点**：语言构成显示 JS、测试命令走 `npm test` 一类。

> 备选：`cookiecutter/cookiecutter`（脚手架场景）、`camelot-dev/camelot`（PDF 抽取，
> 依赖较重，仅作备用）。

## 3. 追问三连（挑一步现场演示）

在任意一步下方点：

1. **「这步太粗」** → 返回更细的子步骤（按该步阶段检索对应视角）
2. **「看不懂为什么」** → 返回这一步的原理/背景（检索 V1/V2）
3. **「报错了」** → 粘贴一段报错日志 → 本地规则先给定位方向；
   配置了 LLM 时再结合仓库上下文补充

**演示用报错样例**（可直接粘贴）：

```
ModuleNotFoundError: No module named 'requests'
```

---

## 4. 收尾话术（30 秒）

- **可验证**：四层评测（L1 烟测 / L2 黄金评估 / L3 消融 / L4 真实贡献），
  质量数字只报人工复核过的仓库集。
- **不编造**：每条断言都能点回真实文件或 issue，不能确认的标 `missing` 并建议提问。
- **可回馈**：用本产品自己走通一个真实 PR（L4 记录，见 `benchmark/l4_contribution/`）。

---

## 5. 风险与兜底

| 风险 | 兜底动作 |
|---|---|
| 现场网络差 / GitHub 限流 | 提前预热（§0）；或直接演示已生成的路线图与本地缓存 |
| 没配 LLM Key | 用「快速(本地规则)」按钮，功能完整只是不调用大模型 |
| 某个仓库抓取失败 | 换 §2 的备用仓库；或展示 `benchmark/reports/` 里的既有结果 |
| 页面报错 | 检查后端 `/health`；重启后端后再试 |
