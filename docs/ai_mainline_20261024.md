## 本轮改动

1. 模型连接在响应前提前关闭时，产品最多有一次重试，分配剩余网络等待；实际请求与重试次数可查看。超时、认证失败、限流和非法 JSON 不通过该恢复路径重试。GitHub 的幂等 GET 也可在提前断连后有界重试一次。
2. 产品使用较紧凑的输出要求，并提供已按原文核验的操作/版本入口。AI 的有效步骤保留，缺失组件和运行时要求由规则补齐，阶段与每一步分别标注来源。来源存在但引用/操作未通过核验的 AI 步骤不当作有效成果保留。
3. 保持原文基础顺序：取得本地副本、运行时前提、环境/依赖、测试。补齐时按规则骨架插入 AI 解释，避免把克隆提示放在安装后。
4. 产品可在实际源文件支持的条件下修正模型的来源类型字段，并将引用的连续空白还原为原文；不改词、不补路径、不改命令参数。明确的 missing 不靠此路径变成事实。严格实验默认仍使用原有逐字核验路径。
5. 识别 `No module named pytest` 等 CLI 错误。缺依赖时给出同组件、同目录、已核验的原文安装入口，不按报错包名拼接安装命令；用户仍需核对并实际重跑。
6. 上游完整 JSON 可选流式接收（`LLM_STREAMING=true`）；收齐后才解析并核验，未完成/截断输出不当作成功。部分内容已收到而连接中断时，不通过产品的断连恢复路径重发。研究客户端保持显式非流式默认。

当前产品默认 `LLM_STREAMING=false`。同一完整输入的四次对照中，流式两次成功、普通响应一次成功一次断连；扩大到六个产品案例后，流式仍有阶段失败，因此没有仅凭前四次试跑把它设为默认。该选项不改变系统代理、TLS 校验、模型服务或凭据。
