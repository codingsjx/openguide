# AI 请求与逐步讲解修复（2026-10-25）

网页产品现在先按固定版本原文建立并核验操作流程，再按每批最多六步生成 AI 讲解。命令、目录、引用、前置关系和执行状态不会被模型改写。所有阶段均可获得讲解；没有仓库专属依据的 Git 起步、选题和 PR 准备仅标为通用说明，不能据此声称存在候选任务、贡献规范或实际改动。

## 修复的具体问题

- 旧流程让模型同时生成操作、引用和说明，少量格式/路径错误可能使阶段回退。新流程固定操作，仅接受与步骤 ID 对应的解释文字，保留已成功条目，最多补生成一次遗漏/无效条目。
- 真实响应曾在 JSON 字符串中途结束。现在使用小批次和更充足的输出预算，并拒绝服务报告为 length 的响应；不修补缺失括号或接受半份 JSON。
- 修正否定成功声明、中文语句中提到 pytest/pnpm，以及同组件已取得清单文件被误判的问题。原文中的确切命令可在解释中被提及，新增参数、新命令、跨组件猜测路径仍被拒绝。
- 暂时性的 502/503/504 与提前断连共享最多一次恢复机会，并只使用剩余网络等待；认证、限流、超时和收到部分流式内容后不会通过此恢复路径重发。研究客户端默认不启用新增服务重试。
- 各批次还受四倍所选等待值的总预算约束。页面明确显示每批次设置、讲解覆盖数、实际请求及两类恢复次数；网络等待不等于整个流程的硬截止。
- 问答按要点核验，保留合格内容并说明已删除的要点及回答可能不完整；没有把整份响应的一个错误等同于所有要点失败。全部不合格时仍回退原文。
- 模型设置留空时沿用当前页/后端值，避免只改模型却自动换到官方地址。已配置时无需重新填密钥；“已填写”明确不等于服务可用。

AI 讲解为新增字段，不进入学习进度的操作身份。相同操作流程重新获取讲解时，不会仅因讲解文字不同而丢失原有笔记或完成记录。
