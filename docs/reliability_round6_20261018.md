保持项目方向与申报选择。独立人工复核仍待完成，无真人实验结果。

## 修复与验证

1. 固定 SHA 的公开文件优先经 GitHub 原文服务下载，再回到同 SHA 的 Contents API；独立 HTTP 客户端不带 API 令牌，不跟随重定向，流式下载限 200KB。分支版本不走此路径，不把错误页作为资料。
2. 文件失败警告列出数量和前五个路径，便于定位缺口。新仓库元信息等 API 仍可能限流；错误提供本地配置或稍后重试的操作说明，首页错误持久展示。
3. 低星标与低提交量只形成核对提示，不再作为拒绝依据或被描述成无人维护。许可证和入口文档约束继续保留。
4. 等待页显示实际经过秒数，提供取消等待。取消不保证停止后台同步处理，页面明确说明；新请求不再被旧响应覆盖。修复 React StrictMode 初次挂载重放造成请求被误取消的问题。

真实 Requests 采集从上一轮演示的 2 份文档恢复到 24 份，其中本次有 22 份来自固定版本原文服务。安装、测试与贡献规范均有检索来源，issue 资料为空；语言信息仍标为未取得。完整记录：`output/qa/live-collection-recovery.json`。此次采集不运行命令，也不代表新手完成贡献。

额外尝试读取 pallets/click 时，仓库元信息接口仍返回 403，未取得该仓库新数据。这说明原文下载优化不能代替 API 身份配置或额度恢复，不能据 Requests 单例宣称任意仓库稳定可用。

在线指南客户端另设单次 HTTP 超时 25 秒、不重试，超时明确回退规则生成；这不是端到端总时限，资料获取和多阶段生成仍需时间。离线实验客户端默认策略保持不变，旧实验结果不冒充新策略的模型结果。

本轮后端与评测 170 项通过；前端 9 项导入测试、lint、类型检查与构建通过。仍存在既有依赖弃用及前端大包提示。浏览器中验证取消可恢复操作。最终现场 AI 请求完成 12 步（A 3、B 1、C 1、D 7），测试命令引用 Makefile 第 5 行，PR 起始步骤引用贡献指南第 70 行；没有执行命令或标记完成。该请求在超时策略变更前启动，不能用于证明新超时策略的成功率。画面见 `output/qa/recovery-test.png`、`recovery-pr.png`，等待画面为 `recovery-wait.png`。
