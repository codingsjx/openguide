# OpenGuide 作品说明

**作品名称**：OpenGuide开源贡献向导
**申报方向**：方向一“开源赋能的 AI 应用创新”，保持原申报选择。
**文档版本**：2026-10-24 收尾候选；程序基线 b4dfc86（含页面会话隔离与条件性安装修复）。独立人工复核、真人效果及团队提交审核未完成。

## 1. 问题、用户与方案

目标用户是具有基础编程能力、尚不熟悉开源贡献流程的学生。首次贡献前，安装依赖、选择执行目录、找到测试入口、核对任务状态与准备 PR，往往需要在 README、贡献规范、构建文件和讨论中来回查找。

OpenGuide 从实际取得的公开仓库资料整理环境、测试、选题与 PR 准备路线；每条操作保留出处及核验等级，资料缺失时明确待确认。它辅助理解和准备，不替用户执行命令、认领任务或保证 PR 被接受。

目前没有正式用户实验。需求来自问题分析与真实仓库使用/失败案例，不能据此宣称已提高新手成功率或节约某个比例的时间。

## 2. 核心流程与功能

| 阶段 | 已实现内容 | 使用边界 |
|---|---|---|
| 仓库读取与体检 | 语言、文档入口、构建文件与子组件、任务采样及规则判断 | 未取得的信息标明未知；规则建议不是对仓库质量的客观认证 |
| A 环境准备 | 克隆入口、原文运行时要求、依赖命令、工作目录与输入路径 | 目录推导与原文要求分开；原文明示的条件性 extras 安装标为可选且不作为默认测试前置项；未知目录不猜测 |
| B 测试基线 | 区分普通测试、构建及专项检查，展示前置条件 | 部分测试通过不代表全量成功；未执行时不预填成功 |
| C 任务准备 | 有状态说明的候选快照、检索入口、人工选题与范围记录 | 标签和采集快照不保证任务无人负责或适合新手 |
| D PR 准备 | 实际文件/diff、修改说明、验证记录与待审阅草稿 | 无实际改动不能生成完整草稿；草稿仅本机整理，不自动提交 |
| 随步帮助与问答 | 细化、当前命令解释、日志定位、同版本贡献问答与原文链接 | 常见命令说明来自通用工具规则；报错方向不等于确认根因 |
| 进度与恢复 | 按指南身份保存进度、卡点、实际执行摘要，导出/恢复准备记录 | 手动状态与执行事实独立；不同仓库/版本/流程不自动迁移完成标记 |

页面支持 AI 与快速原文整理两种生成方式。AI 指南按阶段保留成功结果，失败阶段明确回退；问答无足够依据或模型解读未通过核验时保留原文。保存指南可离线展示，重新联网后才启用实时问答与体检。

## 3. 架构、技术贡献与 AI 作用

处理链路为：公开资料采集与固定版本 → 四视角索引 → 分阶段生成 → 原文/命令核验与流程整理 → 向导、问答和贡献工作台。

| 自主实现部分（含 AI 辅助开发） | 具体设计 | 可以证明什么 |
|---|---|---|
| 四视角检索 | 入口规范、目录架构、可执行路径、任务信息分别组织，按问题和阶段路由 | 可检验任务路由是否影响资料覆盖；并未证明普遍优于全局 RAG |
| 证据约束 | 精确来源、行号、逐字引用、命令动作与参数校验，固定版本链接 | 来源与原文相符；不能直接证明建议语义正确或命令运行成功 |
| 工作流整理 | 原文目录切换、组件识别、输入路径、前置步骤及有限 make 展开 | 可解释操作位置和顺序；复杂脚本不自动改写 |
| 生成与交互恢复 | 分阶段回退、等待/取消、离线快照、卡点与实际结果记录 | 使用路径可继续，失败不伪装成模型成功或测试成功 |
| 可复核评测 | 固定输入哈希、同输出审计、失败/耗时/用量、实跑计划与测试工具 | 支持复现与诊断，不将工具齐备当作效果提升 |

AI 用于依据检索上下文生成指南说明、整理贡献问答，以及在日志定位时选择可核验原文。仓库采集、命令校验、目录与流程推导、当前命令通用解释和进度管理由确定性代码处理。普通模型能力属于外部服务能力；本仓库的贡献在资料约束、流程编排及交互验证。

默认检索使用本地确定性词元重叠，不下载嵌入模型。Chroma 与 sentence-transformers 是可选依赖；当前这些实验不作为向量检索效果证据。当前接口使用 Chat Completions 兼容服务；服务报告的模型名不等于独立确认实际权重身份。

### 4.4 真实模型公平对照

另一次产品端真实 AI 请求（每阶段模型等待 25 秒）在 35.686 秒返回 HTTP 200，但所有阶段最终均为规则整理：A/D 为 model_error、B 为 incomplete_workflow、C 为 no_stage_evidence。HTTP 200 仅代表应用返回了指南，不代表 AI 生成成功；详见 live-ai-product-validation.json。

## 5. 部署、隐私与资源边界

默认 Docker Compose 仅将 8000、5173 绑定到 127.0.0.1，本机直接开发可使用 Vite 同源 API 代理。需要公网部署时，须另配访问控制、TLS、出口/请求与费用限制及日志治理，页面会话隔离不能代替这些措施。

页面临时模型设置按随机页面令牌隔离，仅在后端内存保存；刷新生成新令牌，进程重启清空，闲置超过 30 分钟下次访问失效，最多 128 会话。服务端 .env 是部署者自行保存的默认配置，不能描述为“所有密钥永不落盘”。

AI 指南发送仓库片段；AI 问答还可能发送用户问题及有限先前问题；日志定位可能发送脱敏日志。API 密钥只用于向所选端点认证，不写入提示或回显。关闭模型不等于在线分析不访问 GitHub。学习记录在浏览器本地保存，贡献表单与问答主要保留在当前页，用户主动导出可能包含路径、diff 或个人摘要。

项目自主实现部分按 MIT 开放，依赖和服务保留各自权利。第三方资源清单与许可核对状态作为本报告附件；团队仍须实际审核 API 服务条款、依赖义务、AI 辅助产物及公开范围。详细数据流见 privacy_and_license.md，资源与服务见 third_party_disclosure.md。
