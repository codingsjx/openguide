Click 的范围不评价专项测试是否适合新手，不将已通过的直接 pytest 基线当成 tox random/stress 已通过。两个仓库范围不同，不可据此合并宣称全流程成功率。

复核人应独立执行以下步骤，并在真实完成后填写记录：

1. 检出指定 commit，核对每一项来源文件、行号和原文，确认快照没有错用其他版本。
2. 核对参考命令的动作、参数、执行目录、前置依赖和适用平台；必要时补充有依据的等价命令，不按模型输出倒推答案。
3. 区分“原文明示命令”“建议选择合理”“实际执行成功”；三者分别记录，不互相替代。
4. 核对已有执行报告的提交、命令、目录、环境与通过/失败/跳过范围。对未运行的命令保留未运行。
5. 若有不同意见，先记录分歧与理由，再修订参考版本；保留修订历史和所用评测版本。
6. 完成人工复核后，真实填写复核人和日期。`self_reported_complete` 是团队声明，不是工具独立核实了复核人的身份。

建议记录字段：

```csv
repo,commit_sha,step_order,reviewer,review_date,source_ok,command_ok,cwd_ok,execution_status,disagreement,resolution
```

目前 `quality_claim_eligible` 必须保持 false。源码规则校验通过，只证明指定引用与命令能在所选提交中找到，不能证明语义完整或用户效果。
