# 新手贡献流程补齐与证据（2026-10-25）

本轮保持“帮助新手准备第一次开源贡献”的方向。文章提供流程设计参考，实际修复与测试另有记录；不把教程、代理验收或测试数量当作真人效果。

## 本轮修复

1. **贡献表单不再随生成过程丢失。** 原指南保留到新结果成功返回；表单和草稿另存于本页会话内存，按仓库和指南资料版本隔离。同一版本重新生成、更换工作流身份、离开后返回原仓库可恢复本页准备内容。刷新/关闭仍需先导出，未将原始 diff 自动写入 localStorage、后端或模型。
2. **问答恢复正确测试片段。** 组件过滤不再把公共测试章节换成第一个安装章节；操作型问题优先检索相应操作，并过滤明确属于其他组件的命令。模型空要点不再删除独立核验的操作；覆盖率等未取得的结果仍保持未知。
3. **任务卡从计划到实际结果。** 分别记录问题来源、验收标准、处理边界、修改前观察和实际差异。仅选择方向或填写计划不能生成可提交草稿，新增验收标准缺失时保留待补项。
   选择方向后还能查看当前仓库已核验的说明/测试入口，并回到对应步骤核对前置条件。入口仅复用固定版本的真实文件与命令，不把它们当成已发现的缺陷。
4. **基线与修改后验证分开。** 学习进度单独显示已填写执行情况的数量；可引用真实填写的执行记录作为基线，不把阅读核对、建议命令或此前的通过状态自动变成本次改动通过。修改后的测试还需实际命令、目录、范围、退出码和摘要。
5. **保留旧准备记录兼容性。** v1 JSON 可继续导入，缺失的新字段留空，不伪造验收标准或测试范围；整理新草稿时提示需要补齐的信息。

## 当前证据能支持什么

- 文章支持过程设计选择，不能证明本项目节省时间或提高成功率。
- 同输入对照和浏览器复现支持这两个具体缺陷已修复，不推广成所有仓库都能跑通。
- 实际 patch 与测试结果支持该代理案例的修改/验证确实发生，不表示系统自动完成贡献、真人任务成功或上游 PR 被接受。
- 真人试用与独立解释语义复核继续 pending；未增加模拟参与者或改写历史失败。

后续验证应预先固定任务与完成标准，分别检查“找到有依据的小任务、完成真实差异、记录相关检查、生成可审阅草稿”，并保留求助、超时和失败。无 issue 的探索任务与此前以开放 issue 为目标的协议需分别报告，不混用 `issue_ok` 统计。
