# 国赛完善与验收记录

本项目保持“帮助新手完成第一次开源贡献”的原方向。本记录不构成获奖保证。

## 已实现的可信性修复

- 来源路径必须精确存在；真实目录不能替虚构文件背书。
- GitHub URL 必须属于当前仓库，文件 URL 必须使用当前分支。
- 行号必须落在已抓取原文范围内；引用必须在对应原文中出现。
- 命令必须出现在指定原文中，否则隐藏命令并提示先确认操作。
- 证据分级：`source_exists` 仅证明来源存在；`quote_verified` 证明原文匹配；`command_verified` 证明命令原文匹配。均不证明命令已成功执行或建议语义必然正确。
- 缺失证据不能用随意相关的检索结果补齐。
- 模型失败时产品明确显示规则生成；真实模型评测使用严格模式，禁止静默回退。
- 命令评分保留动作、对象与参数，取消首词相同即正确的宽松规则。
- 步骤采用一对一匹配，增加命令覆盖率，防止删除困难命令造成指标虚高。
- 索引重新构建替换旧内容，清空消失的视角；向量距离转为越大越相关的分数。
- 仓库文档抓取有上限，收录 CI workflow；近 30 天活跃度依据实际提交日期。
- Issue 候选展示采集时的开放状态、负责人数量、讨论锁定及更新时间；审计后的指南不将标签视作可直接认领证明，缺失字段明确未知。最新讨论和关联 PR 仍需用户打开原始 issue 核对。
- 已采集的嵌套 CONTRIBUTING（含 RST）、行为规范及 PR 模板进入贡献规范视角；不代表已发现仓库所有规范文件。

## 真实模型实验

```powershell
python -m benchmark.controlled_ablation --repos pallets/click --repeats 1
```

四组为单次生成、全视角普通 RAG、四视角分阶段生成、对同一份四视角输出进行证据审计。
普通 RAG 和四视角使用相同阶段提示、top-k 和输出 token 上限；两者均使用已有视角分块，因此检验的是路由，而不是全新的通用 RAG 实现。
单次生成的调用次数与输入预算不同，仅作为产品基线，不能单独用于证明路由机制有效。
证据审计前后复用同一份生成，避免把模型采样差异当成机制收益。

每轮保存 commit SHA、输入快照哈希、golden 参考、提示与原始响应、服务报告的模型 ID、token 用量、耗时、失败状态。
模型身份以第三方服务返回为准，不宣称已独立验证模型权重或开源属性。
命令不自动执行；`command_exec` 在此实验中未测。旧 golden 尚需按本轮 SHA 人工复核，自动得分是探索性结果。
当前实验使用本地词元检索，不把结果泛化成已验证的向量模型效果。

## 第五轮真实采集与观察记录

在线文档采集先解析固定提交，同步固定根目录、文件树、文档请求和指南证据链接。无法解析提交时失败，不混用变化中的分支内容。GitHub 截断文件树标为未取得，文件超时和部分文档缺失明确降级。补齐 `.github` 下规范和多模板目录采集；扫描普通文档达到上限后仍继续寻找关键规范。

真实 GitHub 检查取得 `codingsjx/openguide` 提交 `8c21e6d43798c707b5aa5001112719e832ae95a8` 的 139 个文件路径及 7 份文档；本机 HTTP API 复验返回固定提交。见 `output/qa/revision-collection-check.json` 和 `output/qa/pinned-guide-api-check.json`。这是在线采集与规则生成检查，不是模型效果、新手实验或上游命令执行。首次 HTTP 请求碰到旧热重载进程，重载后的重复检查通过；记录保留该情况。

`benchmark.user_study` 提供本地台账结构、分组/同意/限时校验及保留缺失和退出的描述性统计。空台账仍是 0 位参与者、无成功率；工具不认证人工观察的真实性，不上传原始记录。团队可按 `docs/user_study_protocol.md` 开展实验。
