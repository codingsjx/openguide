# 入门流程补齐与真实网页复验

本轮沿用“新手完成首次开源贡献”的项目方向，针对上一轮实测卡点修改主体功能。不是人工试用，也不构成获奖结论。

## 实现变化

- **体检识别子项目**：取得固定提交的文件树，列出根目录和四层以内的组件配置，排除 vendor、依赖、构建产物和符号链接，最多展示 24 份。展示实际路径和固定版本链接，区分完整文件树、部分目录和资料不可用。不再仅凭 pyproject/package.json 文件名推测 uv、pnpm、pytest 等工具与命令。
- **运行时前提进入指南**：从实际已取得的 README、requires-python、Node engines、版本文件提取逐字引用及真实行号；不编造安装方法。产品模式会补齐模型遗漏的这类前提，记录为规则补齐；严格模型实验不补齐。
- **步骤细化可操作**：分别展示工具提供的准备检查、仓库原文要求、已核验的当前命令与执行目录、结果检查和异常入口。过滤其他组件及普通场景不相关的 CI/示例资料。请求中附带的命令和目录不能直接当作证据，必须重新核验、推导。
- **通用入门帮助**：单独标明标准 Git 克隆提示及 PR 准备清单是工具提供的通用操作，未执行，不冒充仓库政策。仓库缺少专属 PR 规范时仍明确待确认。
- **问答等待和导出**：页面提供 25/40/60/90/120 秒选择；后端接受整数 10–120 秒，默认 40 秒，无交互重试。浏览器整次等待为模型预算加资料采集余量。设置独立于指南，导出保留本轮等待设置和执行目录。
- **空资料不空等模型**：产品模式没有检索片段的阶段直接保留规则入口，记录 `no_stage_evidence`，页面说明未调用模型。严格实验仍按原协议请求模型。新增网络耗时与状态诊断不记录密钥、URL、提示词或服务商响应正文。

## 模型结果与边界

第一份实际 AI 记录 `live-ai-guide.json` 使用每阶段 60 秒，发生在空资料跳过逻辑加入之前：A 因遗漏操作/前提使用规则补齐，B 保留 AI，C 和 D 超时回退。没有把它统计为完整 AI 成功。

加入跳过逻辑后，暂用每阶段 10 秒进行边界验收，保存为 `live-empty-context-guard.json`：C 明确为 `no_stage_evidence`，其余模型超时仍如实保留。随后恢复浏览器原先的 60 秒指南偏好。10 秒与 60 秒记录不能用于推导速度提升比例；空资料不请求模型由回归中的调用计数和实际返回原因共同验证。

最终 60 秒问答返回了模型结果，但 AI 解读未通过核验；原文回退保留了核心操作。本轮没有取消引用核验，也没有声称模型稳定性已经解决。

构建仍有单个较大 bundle 的提示；本轮未做加载性能结论。静态目录、文字和命令核验不等于语义正确、安装成功或测试通过。没有运行被分析 master 版本的安装/测试命令，没有自动提交上游 PR。真人试用、独立复核、多仓库效果实验及有效贡献结果仍需补充。
