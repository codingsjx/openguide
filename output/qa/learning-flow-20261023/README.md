# 新手持续辅导流程优化与验收

本轮保持项目原方向，修改前端辅导流程，没有修改后端生成、证据校验或模型配置。

## 辅导流程

按“阶段目标 → 前置检查 → 操作与出处 → 记录结果 → 卡点排查 → 暂缓或恢复继续”组织辅导：

- 展示本阶段目标及手动核对、卡住、暂缓数量；可打开完整步骤目录返回对应位置。
- 当前命令的前置步骤尚未记录完成时，显示直接返回该步骤的按钮。用户自行标记不代表依赖已经验证，导航仍可自由浏览。
- 每步可以写最多 1000 字符的摘要。卡住时展开排错输入并聚焦；原始日志仍只保留在当前步骤的组件内存中，不自动写入学习记录。
- 完成按钮明确为“记录完成并继续”；暂缓与浏览不计为完成，可以撤回完成标记或改为待继续。
- 按仓库、资料版本和完整步骤内容绑定本机记录；同一指南离线导入可继续，其他仓库、版本、不同操作和静态示例不混用完成状态。
- 首页提供“继续上次指南”，从本机快照恢复学习位置和摘要；明确标为本机查看，未重新核验资料。问答历史、排错日志和贡献工作台表单不纳入该自动保存。
- 浏览器存储失败或记录过大时提示导出，不把无法恢复的记录宣称为已保存；Markdown 导出区分使用者记录与系统验证。
- 首页在读取仓库前可选 AI 或快速原文整理。自动生成在开发模式的 effect 重放清理后调度，避免重复的自动请求。
- 细化结果中的运行时要求改为带出处的紧凑列表，保留命令、执行目录及三段核对流程。手机端阶段导航保持横排，保存说明默认折叠。

## 实际网页检查

本轮使用真实页面 `http://127.0.0.1:5179/`，从首页选择快速原文整理，读取 `codingsjx/openguide` 默认 master 的固定资料提交 `8c21e6d43798c707b5aa5001112719e832ae95a8`，实际生成 11 步。保存的 `guide.json` 是从页面下载的真实规则指南，不是 AI 效果实验。

1. 跳到后端测试第 8 步，出现前置第 6 步尚未记录完成的提示；点击可返回后端安装。
2. 为覆盖状态联动，在第 6 步填写明确标注“页面验收模拟，未执行命令”的摘要，再手动标记完成；回到第 8 步后，该手动前置提示消失。没有把它当作安装成功证据。
3. 第 8 步填写模拟卡点并展开排错，输入合成日志 `NOT_A_REAL_TEST_LOG`，未点击“定位问题”，没有向模型提交该日志。
4. 仅浏览下一步后，卡点仍保留；通过步骤目录返回时摘要仍在，而原始日志输入框为空。
5. 刷新页面后，首页显示继续入口；点击后回到第 8 步，并恢复手动状态和摘要。快照视图保持问答及体检禁用，不冒充实时读取。
6. 导出 `learning-demo.md` 保留了模拟摘要、手动完成 1/11 和卡住状态，不包含合成原始日志。该文件是 UI 验收样例，不是用户实验数据。
7. 选择暂缓后，卡住变为 0、暂缓变为 1，完成数没有增加；随后撤回全部验收用状态。最终 `learning-final.md` 是手动完成 0/11，模拟摘要保留且明确已结束。
8. 重新从首页用快速模式取得同一组真实步骤后，原有学习位置与摘要仍可恢复，在线体检和问答标签重新可用。
9. 实际请求后端安装的“这步太粗”，运行时引用紧凑展示，命令仍为 backend 目录的 `uv sync`，出处及结果检查保留。
10. 手机模拟的实际 CSS 视口宽度为 375 像素，文档宽度同为 375，无横向溢出；已恢复正常桌面视口。

对应页面文本为 `01-prerequisites.txt` 至 `09-final-workspace.txt`，截图为 `01-resume-home.png`、`02-mobile-learning.png` 和 `03-learning-workspace.png`。
